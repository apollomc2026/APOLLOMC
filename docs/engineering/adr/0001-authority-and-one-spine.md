# ADR 0001: APOLLO 3.0 authority and one execution spine

- Status: Accepted
- Date: 2026-09-06

## Context

APOLLO contains four partially visible implementation eras. The historical repository plan encodes a taxonomy-first product, while the authoritative guiding light requires conversational mission discovery and verified professional deliverables.

## Decision

The Deliverable Specification is the immutable semantic control plane. Conversation proposes and revises it; explicit approval authorizes execution; every run references its exact version. All generation converges on one durable document-job executor. Legacy endpoints may exist only as measured, time-bounded adapters.

Hostinger replaces the GoDaddy web-hosting tier only. It does not absorb Vercel, Supabase, Drive, AWS or Google Workspace mail.

## Consequences

- New data contracts are additive and tenant-scoped.
- Every exposed Supabase table receives explicit grants and RLS policies; exposure is never assumed.
- No new generator or delivery path may bypass the canonical executor.
- Retirement requires caller telemetry, data/deployment proof and rollback evidence.
- Historical documents remain evidence but cannot silently override the guiding light.
